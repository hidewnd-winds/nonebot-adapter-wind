# 协议能力矩阵

Wind 扩展复用官方适配器的连接与原生 API，在明确支持的消息类型上提供统一业务 API。该表描述 Wind 统一层能力，不代表上游 SDK 的全部事件都可转换成统一消息。

| 能力 | QQ | OneBot V11 | 说明 |
|---|---|---|---|
| 群/私聊 `UnifiedMessage` | 支持所实现消息事件 | 支持所实现消息事件 | 其他事件使用上游原生事件或自身处理器 |
| 文本、图片、真实提及、引用元数据 | 支持 | 支持 | 具体平台事件提供什么字段决定可用信息 |
| `Document` | 原生 Markdown、可选键盘 | 纯文本与真实 `at` 段 | 样式与按钮按平台降级 |
| 图文复合 | QQ 原生消息及图片发布需求 | 保序媒体消息 | 不同传输可能有消息合并差异 |
| 回复原消息 | 受凭据有效期及 `msg_seq` 约束 | 消息段引用与原消息查询 | QQ 过期后允许受限普通发送降级 |
| `RichContent.single_message` | 平台组合能力允许时支持 | 平台组合能力允许时支持 | 不可合并时明确失败，不自动拆分 |
| 群资料、成员和群列表 | 支持已映射接口 | 支持上游暴露的接口 | 平台权限或字段缺失时保持未知 |
| 群状态与禁言 | 支持并按 Bot 限流 | 支持能力有限 | 不支持的能力抛 `UnsupportedProtocolCapabilityError` |
| 入群申请和审批 | 支持真实 QQ 申请标识 | 支持 `flag` 和 `sub_type` | 宿主负责审批权限、队列和业务理由 |
| 黑名单及成员管理 | 支持平台接口 | 受协议 API 限制 | 部分失败返回/抛出带已完成信息；写操作不自动重放 |
| QQ 键盘交互事件 | 支持 | 不适用 | QQ 专有；必须校验回调授权 |
| QQ 指令面板 | 支持查询/创建/更新 | 不适用 | 无导入或启动自动写入 |
| 传输及认证 | 官方 QQ Adapter 机制 | 官方 OneBot Adapter 机制 | 不重复实现官方协议栈 |

官方原版和 Wind Adapter 的注册名相同。同一进程应选择该协议的一种实现；Wind 提供注册辅助函数，在注册前检查冲突。当前不能保证之后直接调用官方 `driver.register_adapter()` 时一定报错，因为 NoneBot 对重复名称可能静默忽略。

真实平台权限、凭据有效期和特定错误响应会随 SDK、平台策略变化。文档中标记为受限或未实测的能力，不应被理解为所有生产账号都可用。

## 明确支持的统一事件与发送差异

QQ 统一消息转换仅接受 `GroupAtMessageCreateEvent`、`GroupMessageCreateEvent`、`C2CMessageCreateEvent`；OneBot 接受 `GroupMessageEvent`、`PrivateMessageEvent`。QQ 频道事件等原生事件仍可通过 SDK 处理，但不因此获得统一转换。QQ 交互通过专用辅助接口构造群聊上下文。

OneBot 的当前群会话多项内容走合并转发；私聊多项内容逐条发送；无会话主动发送把内容合为一个平台 Message。请求引用源消息时使用 reply 消息段，并按原路径组合。QQ OrderedContent 保留文本/图片位置，可能拆成多条平台消息；不会强行统一为 OneBot 的发送条数。`single_message` 是单个 RichContent 的约束，不是跨整个内容序列的事务：前一个内容已发送后，后一个内容校验失败不撤销前者。

OneBot 不支持列举待审批申请、独立群黑名单查询/增删或完整禁言计划查询等标准协议没有的能力；事件中的真实申请仍可审批，成员移除可传 `reject_add_request` 对应选项。QQ 平台能力同样取决于账号权限，离线映射通过不等于真实平台授权。
